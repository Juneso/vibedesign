# M2 평가 루브릭 v1

> DES-188. 3개 파이프라인(A Ingest / B Profile / C Nudge) × 다축 평가.
> 점수: **2(통과) / 1(부분) / 0(실패)**. 축별 0이 하나라도 있으면 케이스 fail.
> 자기평가는 Claude가 1차 채점, 의심 케이스만 사용자가 최종 검토.

---

## 파이프라인 A · Ingest (메모 → wiki patch)

### A1. 출처 강제 (Source-binding)
- **2**: 모든 wiki 페이지의 sources[] 에 입력 메모 ID 또는 book-meta ID가 명시되고, 페이지 본문의 모든 주장이 sources 중 하나로 역추적 가능.
- **1**: sources 는 있으나 일부 문장에 근거 매핑 불명확.
- **0**: 근거 없는 자유 서술, llm-inference 미표시, 또는 sources 빈 배열.

### A2. 책 맥락 매핑

**먼저 입력의 `book.toc.length` 를 본다.**

**Case-A: toc 가 6항목 이상 (정상)**
- **2**: 메모의 page/chapter 가 toc 항목과 정확히 매칭됨.
- **1**: 장은 맞으나 절 누락, 또는 한 단계 모호.
- **0**: 엉뚱한 챕터로 분류.

**Case-B: toc 가 5항목 이하 (빈약 — 예: 조르바)**
이 경우 tocAnchor 가 "미지정" 인 것은 **정상**이고 점수와 무관하다. 매핑 점수는 `bookContextLink` 의 질로 판단:
- **2**: 모든(또는 거의 모든) bookContextLink 가 [책 보강 컨텍스트]의 책소개/책속에서/추천글에서 *실제 문구를 인용하거나 명확히 참조* 해 책 전체 주제와 메모를 연결. 출처 field 명시(예: "(책속에서: ...)"). tocAnchor="미지정" 은 감점 없음.
- **1**: bookContextLink 가 책 보강 컨텍스트를 일부만 활용하거나, 인용 없이 일반 요약만 함.
- **0**: bookContextLink 가 "책 요약/목차에 명시되지 않음" 류로 도망가거나, 빈약 toc 를 무시하고 가짜 anchor 를 만들어 anchorConfidence:"high" 로 단정.

> 이 분기를 무시하고 "tocAnchor=미지정 이면 무조건 0" 으로 채점하지 말 것. 입력 toc 길이를 먼저 확인하라.

### A3. 키 개념 추출의 비자명성 (Non-triviality)
- **2**: 메모 텍스트의 *비자명*한 핵심 개념을 뽑아냄 ("자유", "시장" 같은 단어 자체가 아니라 그것이 메모에서 *어떻게* 쓰였는가).
- **1**: 개념은 맞으나 너무 일반적이거나 메모 1개만 보고도 알 수 있는 표면 키워드.
- **0**: 메모와 무관한 개념, 또는 단순 명사 나열.

## 파이프라인 B · Profile 해석 (직군 → 인지/정서/실무)

### B1. 3축 매핑 충실도
- **2**: 입력 프로필(직군/관심사/고민)에서 인지(어떻게 사고하는지), 정서(무엇에 끌리는지), 실무(무엇을 다루는지) 3축이 모두 의미 있는 derivedKeywords로 도출됨.
- **1**: 3축 중 2축만 의미 있음.
- **0**: 단순히 프로필 단어를 재배열하거나 일반론 ("성장하고 싶다") 반복.

### B2. 출처 추적성
- **2**: 모든 derivedKeyword에 "어느 입력 필드(role/interests/concerns)에서 파생됐는지" 명시. 다른 사용자에게 그대로 적용해도 다른 결과가 나올 정도로 입력 의존성이 높음.
- **1**: 일부만 추적 가능.
- **0**: 어느 사용자에게나 통하는 일반 키워드, 또는 입력 무시한 환각.

---

## 파이프라인 C · Nudge (조건 만족 페이지 → 질문)

### C1. 근거 강제 (Grounding)
- **2**: 넛지의 sourcePageIds 가 wiki에 실제 존재하고, 질문의 모든 명제가 그 페이지들로 역추적 가능. 책 원문 추론 0건.
- **1**: 근거는 있으나 일부 문구가 페이지 밖 지식에 기댐.
- **0**: 책 원문에 대한 추론·인용, 또는 존재하지 않는 페이지 ID.

### C2. 3종 유형 적합성
- **2**: (a)메모-메모 / (b)배경-메모 / (c)책-책 중 하나로 명확히 분류 가능. 분류와 실제 sourcePageIds 구성이 일치.
- **1**: 유형은 맞으나 sources 가 분류와 다르게 구성됨.
- **0**: 3종 외 유형, 또는 잘못된 분류.

### C3. derivedKeywords 활용 (개인화)
- **2**: 같은 wiki에서 다른 프로필을 넣으면 다른 질문이 나올 정도로 derivedKeywords 가 질문 표현/초점에 반영됨.
- **1**: derivedKeywords 가 출력에 등장하나 표면적.
- **0**: derivedKeywords 무시 — 어느 사용자에게나 같은 질문.

## 합격 임계값 (DES-192)

| 파이프라인 | 라운드 1 임계 | 라운드 2 임계 (M2 닫기) |
|---|---|---|
| A (Ingest) | 합격률 ≥ 80% | **100%** |
| B (Profile) | — (라운드 2부터) | **100%** |
| C (Nudge) | 합격률 ≥ 80% | **100%** |

합격 정의: 한 케이스의 모든 축에서 점수 ≥ 1 AND 0점 축 없음. 즉 케이스당 모든 축이 1 이상.

## 사용 흐름

1. `eval/runEval.mjs` 가 seed-v1.json 로드 → planIngest / interpretProfile / generateNudge 호출
2. 각 출력에 대해 Claude가 자기평가 프롬프트로 1차 채점 → `eval/runs/round-N.md` 생성
3. 점수 1 이하인 케이스를 의심 케이스 short list 로 추출
4. 사용자가 short list 만 검토 (5~10분)
5. 라운드 결과 → 다음 튜닝 액션 자동 제안 (어느 축이 가장 약한지)
