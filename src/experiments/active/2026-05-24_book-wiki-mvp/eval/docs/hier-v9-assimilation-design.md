# hier-ingest v9 설계 — 동화 우선 증분 인제스트 (assimilation-first)

> 작성: Claude, 2026-07-07 (Junseo와의 토론 결과).
> 배경: v5~v8 셔플 안정성 실험(관계쌍 자카드 8~14%)이 보여준 결론 — "문장만으로 위계를 생성"시키면
> 모델이 구조를 즉흥 작문한다. v9는 인간의 이해 과정(동화→조절→통합)을 **프롬프트가 아니라
> 아키텍처로** 옮긴다. 오라클 골든: golden/hier-oracle-design-of-design.md(v2), golden/hier-oracle-3books.md.

## 설계 원리 (토론에서 확정된 것)

1. **목차 = 확정 스켈레톤, fog-of-war 노출.** 문장이 붙은 마디만 물질화. 조상 경로는 노출, 형제는 숨김.
2. **문장 데이터가 지지하는 관계는 동일(merge)·군집까지.** is-a 위계는 목차에서 빌린다. 테마는 오버레이.
3. **노드 제목 = 표제어** (2~10자 명사구, 자구 우선, 합성 금지). 논지는 본문 첫 줄.
4. **lift**: 메모 1건 → {표제어, 논지, role, 예시 대상}. role ∈ {정의, 주장, 예시/장면, 독자 정리, 독자 생각}.
5. **기권은 1급 기능.** 미분류 선반 = "아직 소화 안 된 것".
6. **온라인은 add-only, 구조 변경은 통합 패스에서만.** 안정성은 프롬프트가 아니라 이 분리에서 나온다.

## 데이터 모델

```
Memo     { id, bookId, page, quote, myThought, createdAt }
Lift     { memoId, headword, claim, role, exampleOf?, embedding }        # 캐시 영구
Skeleton { bookId, entries[ {idx, title, pageStart?} ] }                 # 알라딘 목차. 잠재 상태
Node     { id, kind: chapter|concept, title, claimAnchor?, memoIds[], chapterIdx?, createdAt }
Shelf    { bookId, memoIds[] }                                           # 미분류
LinkQ    { a, b, kind: same|theme|crossbook, score, status: pending|confirmed }
Digest   { consolidatedAt, changes[] }                                   # 통합 패스 변경 로그
```

## 온라인 패스 (메모 도착마다 · 동화 우선 · add-only)

```
새 메모 m
 1. lift(m)                          # LLM 1콜, 메모 단건, 순서 무관, 영구 캐시
 2. 장 추정: page ↔ Skeleton
    - pageStart 있으면 순수 조회 (LLM 0)
    - 없으면 현재까지 관측된 앵커(자구 일치 장제목 등)로 구간 추정. 확신 낮으면 → Shelf
 3. 동화(assimilation): 같은 장의 기존 concept 노드와 매칭
    - 임베딩 top-k → LLM 판정 "같은 개념인가?" (보수적: 불확실하면 No)
    - Yes → 노드에 memoId 추가. 제목·위치 불변. role=정의|독자 정리면 claimAnchor 승격 후보로 마킹
    - No  → 새 concept 노드 생성 (장 미물질화 상태면 장 노드 물질화 + 조상 경로 노출)
 4. 오버레이 후보 적재: headword ↔ 타 장·타 책 headword 유사도 상위 → LinkQ(pending)
    (온라인에서는 노출하지 않거나 '제안' 배지로만)
```

온라인 패스가 못 하는 것(금지 연산): 노드 개명, 이동, 병합, 삭제, 테마 생성. → 전부 통합 패스로.

## 통합 패스 (consolidation · 주기적/명시적 이벤트)

트리거: 책 완독 표시 / 미분류 N건 누적 / 유저 명시 요청 ("정리해줘").
유일하게 구조를 바꿀 수 있는 시점. 전 연산 근거 게이트 + 변경 다이제스트를 유저에게 보고.

1. **부착 전역 재정렬**: 페이지 정렬 메모열 ↔ 목차열 단조 정렬(DP). 자구 앵커로 경계 고정.
   온라인 추정과 다르면 이동 제안. (v8까지의 '내용만 부착'이 틀리는 지점 — 오라클의 p36 사례 —
   을 여기서 잡는다)
2. **미분류 재심사**: 새 이웃 개념·확정된 경계로 다시 시도. 여전히 불가면 유지.
3. **동의어 병합**: 같은 장 내 headword 쌍 판정. 병합 시 제목 선택 규칙(결정적):
   role=정의·독자 정리 보유 > 자구 빈도 > 짧은 쪽. (온라인의 선착순 제목 편향을 여기서 보정)
4. **테마 승격**: 같은 장 concept ≥3 + 메모 span 기준 충족 시에만 중간 마디 생성
   (v8 theme 기각 로직 재사용 — 실험상 대부분 기각되는 게 정상).
5. **오버레이 확정**: LinkQ pending → 판정 → confirmed만 노출.
6. **다이제스트 생성**: "정리하면서 바뀐 것 N건" — 구조 변화를 유저가 예측 가능한 이벤트로.

## 안정성 논증

- 온라인 add-only → 도착 순서가 만들 수 있는 차이는 (a) 동의어 중 선착 제목 (b) 동화 tie-break뿐.
  둘 다 통합 패스의 결정적 규칙(병합·제목 선택)이 수렴시킴.
- 새 안정성 지표: **수렴 안정성** — 같은 메모셋을 도착 순서 3종(원순서/셔플 시드 7·42)으로 흘리고
  통합 패스까지 돌린 뒤 최종 트리 비교. 목표: 관계 라벨 일치 ≥95%, 관계쌍 자카드 ≥80%
  (v8 실측: 87% / 10%).
- 오라클 일치율: 최종 트리 ↔ hier-oracle 골든 4권. 부착 정확도 / 표제어 일치(동의어 허용) /
  기권 재현(오라클 기권 항목을 강제 부착하면 감점).

## v8 대비 변경 요약

| | v8 | v9 |
|---|---|---|
| 목차 | 프롬프트 힌트("숨은 척추") | 데이터 구조(스켈레톤 + 물질화) |
| 부착 | LLM 자유 판단 | 단조 정렬(조회/DP) + 친화도 |
| 위계 생성 | LLM이 트리 작문 | 목차 위계 차용 + 근거 게이트 승격만 |
| 테마 | 트리 변형(부모 삽입) | 오버레이 (+승격은 통합 패스) |
| 증분 | 없음(배치) | 온라인 add-only + 통합 패스 분리 |
| 안정성 | 프롬프트로 유도 (자카드 10%) | 구조적 보장 + 수렴 안정성 지표 |
