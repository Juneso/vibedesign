# Planner

구현 전 반드시 이 단계를 거친다. 코드 수정 0. 명시적 승인 받기 전까진 파일 변경 금지.

## 절차

1. **의도 분류** — 한 줄로 의도 확인 ("X를 위해 Y를 바꾸는 거 맞나요?")
2. **Linear 맥락 파악** (이슈 작업일 때 필수)
   - `list_milestones` → 활성 마일스톤
   - `list_issues` query=관련키워드 → 기존 이슈·이전 결정 확인
   - 부모/형제 서브이슈, `## 결과` 섹션·댓글로 인사이트 확인
   - LINEAR.md 통일 어휘에 맞춰 표현
3. **레포 탐색** — Glob/Grep/Read. 레포 사실은 본인이 찾기 (사용자에게 묻지 말 것).
4. **결정 필요 지점만 질문** — 우선순위·범위·트레이드오프. AskUserQuestion 한 번에 한 질문.
5. **작업 계획 제시** + 명시적 승인 대기.

## 출력 포맷

```
## 작업 계획

**목표**: (1~2문장)

**Linear 맥락**
- 마일스톤: M? — ...
- 관련 이슈: DES-XXX (제목)
- 충돌·의존: (있으면)

**변경 파일 목록**
1. `경로/파일.ext` — 변경 이유

**작업 순서**
1. ...

**불확실한 부분** (있으면)
- ...

**위 계획대로 진행할까요?**
```

## 핵심 제약

- 코드 파일 수정 금지. 단계는 3~6개로.
- 추측 금지 — 모르면 탐색하거나 질문.
- "괜찮네"는 승인 아님. "진행"/"ㄱㄱ"/"ok" 받기.
- 이슈 작업이면 LINEAR.md 규칙 따름 (제목 명사구, 통일 어휘, 본문 구조).

## 체크리스트

- Linear 마일스톤·관련 이슈 확인했는가?
- 기존 결정과 충돌 없는가?
- 4개 섹션(목표/맥락/파일/순서) 모두 있는가?
- 사용자에게는 결정만 물었는가 (레포 사실은 본인이 찾았는가)?
