# /linear-merge <원본…> <대상> — 이슈 통합

원본 이슈(들)의 내용을 대상 이슈로 옮겨 원본을 지워도 정보가 사라지지 않게 한다.
근거: JSN-167 (0901 사례: 392→389, 394→401, 382→380, 235·236·237→234).

## 절차

### 1. 읽기
- 원본·대상 모두 `get_issue`. 원본에 하위 이슈가 있으면 대상(또는 대상의 하위)으로 `parentId` 재지정 대상에 포함

### 2. 대상에 흡수
- **목표**: 대상 목표 체크리스트에 원본의 일을 항목으로 추가 — `(구 BKT-XXX 통합)` 표기, 완료 여부에 맞게 체크
- **결과**: 원본의 결과·설계 기록을 대상 `## 결과` 에 **콜랩스 하나**로 이관 — 제목에 `(구 BKT-XXX · 커밋 …)` 병기
  - 산출물·설계 이유·동작·한계, **커밋 해시·실측 수치·기각한 실험**을 잃지 말 것 — 이 기록이 통합의 이유다
  - 원본에만 있는 결정(누가·언제)도 보존 (예: "준서 결정 0727")
- 원본이 미완 작업을 갖고 있으면 대상 목표의 **미완 체크박스**로 승계

### 3. 원본을 포인터로
- 본문 전체를 교체: `## ⚠️ BKT-YYY 로 통합됨 (날짜)` + 무엇이 어디로 갔는지 2~3줄
- 상태: 완료된 원본은 Done 유지, 미완이면 Canceled
- 삭제·아카이브는 API 로 불가 — **준서가 직접 지우면 된다고 보고** (GitHub 미러 이슈가 붙어 있으면 그것도 알려줌)

### 4. 역링크 재지정 — 빠뜨리기 가장 쉬운 단계
- `list_issues(query: "BKT-XXX")` + 원본의 부모·형제·관련 이슈 본문에서 원본 링크를 찾음
- 각 링크를 대상으로 바꾸되 맥락 유지: `(구 BKT-XXX → BKT-YYY 통합)` 식
- 최상위 플로우 이슈(`N |`)의 서브이슈 목록·목표 체크리스트도 확인

### 5. 검증·보고
- 저장 응답 본문을 훑어 한글 깨짐·중복 헤더·잔여 앵커 확인
- 최종 트리 모양과 "원본 지워도 됨" 여부를 보고

## 하지 않는 것
- 원본 내용의 요약 축약으로 정보 손실 (콜랩스라 길어도 됨 — 잃는 것이 없어야 지울 수 있다)
- 지시 없는 다대다 통합 (한 번에 대상 하나)
