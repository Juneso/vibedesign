# Figma Make 프롬프트 작성기

Linear에 적힌 기획(예: `BKT-262`)을 **Figma Make에 바로 붙여넣을 수 있는 구조화된 프롬프트**로 변환한다.
목적은 "기획 → 초안 UI"의 첫 한 바퀴를 빠르게 도는 것. 코드 구현이 아니라 **프롬프트 텍스트 생산이 산출물**이다.

> 출처: Figma — *A designer's framework for better AI prompts*
> https://www.figma.com/blog/designer-framework-for-better-ai-prompts/
> 핵심 = **TC-EBC** 프레임워크 + Figma Make 프롬프팅 팁(아래에 내장).

> 참고 — 이 스킬은 **프롬프트 텍스트까지만** 만든다. Figma Make는 MCP로 자동 구동되지 않으므로(MCP는 `/make/`가 아니라 `/design/` 파일만 씀), 만든 프롬프트는 **사용자가 Figma Make 채팅창에 직접 붙여넣어** 초안을 생성한다.

---

## 입력

- **필수**: Linear 이슈 ID 1개 이상 (`BKT-262`, `DES-270` 등). 여러 개면 화면 세트로 합칠 수 있음.
- **선택**: 타깃 플랫폼(모바일/iOS·웹·데스크톱), 톤/레퍼런스, 다크모드 여부, 기존 웹 프로토타입 참조 여부.
- 사용자가 ID만 주면 나머지는 이슈 본문에서 추론한다(묻지 말 것). 추론 불가한 결정만 1개 질문.

---

## 절차

### 1. 이슈 로드
- `get_issue`(id) 로 본문 전체를 읽는다. 본문 내 링크된 의존 이슈(`BKT-329` 데이터 모델 등)도 ID가 보이면 함께 읽어 컨텍스트를 채운다.
- "참고" 섹션에 기존 웹 프로토타입 경로(`screens/*.jsx`, `lib/*.js`)가 있으면 해당 파일을 읽어 **이미 존재하는 컴포넌트·비주얼 언어**를 컨텍스트로 확보한다(TC-EBC: 디자인 시스템/코드베이스를 컨텍스트로).

### 2. TC-EBC 매핑
이슈 섹션을 TC-EBC 5요소로 매핑한다. Booktracking/vibedesign 기획 본문은 대개 아래 구조를 따른다:

| TC-EBC | 의미 | 이슈에서 가져올 곳 |
|--------|------|-------------------|
| **Task** | 무엇을 만드는가 | 제목 + `## 합격 기준` (완성 정의) |
| **Context** | 왜·누구를 위해 | `## 왜 필요한가` |
| **Elements** | 필요한 UI 컴포넌트 | `## 화면 + 플로우`의 화면 요소(input/list/card/CTA/시트/토스트) |
| **Behavior** | 어떻게 동작하는가 | `## 화면 + 플로우` 단계별 동작 + `## 검증·엣지 케이스`(상태) |
| **Constraints** | 가드레일(바뀌면 안 되는 것) | 플랫폼·디자인시스템·`## 의존`·언어·접근성·합격 기준의 제약 |

- API 호출/스키마/백엔드 디테일(알라딘 `ItemSearch`, SwiftData, Firestore 등)은 **프롬프트에서 제거**한다 — Figma Make는 UI를 그리지 데이터를 붙이지 않는다. 단, **화면에 나타나는 결과**(표지·제목·저자·출판사 등 필드)는 Elements로 남긴다.
- 엣지 케이스(중복/0건/실패)는 **빈 상태·에러 상태 화면**으로 번역해 Behavior/Elements에 넣는다. 초안에서 상태 누락이 가장 흔한 손실.

### 3. 프롬프트 조립 — Figma Make 작성 규칙
아래 팁을 **반드시** 반영한다(출처 기사):

- **공손어 제거**: "please", "해주세요", "감사합니다" 금지. 모델엔 깨끗한 지시와 명확한 제약만.
- **스캔 가능·명시적**: 불렛 위주, 동작을 직접 서술. 모호어("적절히", "예쁘게")를 구체 지시로 치환.
- **뺄셈의 미학**: 불필요한 수식 제거. 작업을 인사말 속에 묻지 말 것.
- **제약으로 "바뀌면 안 되는 것" 고정**: 플랫폼/모드/언어/디자인 톤을 Constraints에 명시.
- **컨텍스트로 디자인 시스템 지정**: 참조할 라이브러리·기존 프로토타입·톤이 있으면 명시.
- **더미 데이터 지시**: 한국어 단행본 등 현실적인 더미 콘텐츠로 채우라고 명시(빈 깡통 화면 방지).
- **상태 망라**: 기본/빈/로딩/에러/성공 상태를 화면으로 요구.
- (Figma Make 안에서 사용자가 직접 할 일) 스크린샷이 아니라 **프레임**을 첨부하고, 수정은 Constraints 섹션을 갱신해 "무엇을 바꾸지 말지"를 고정하라고 한 줄 안내.

### 4. 출력
TC-EBC 본문은 한국어로, **복붙 가능한 코드블록 1개**로 낸다. 화면이 여러 개면 "Screens" 목록으로 나열한다.

---

## 출력 포맷

````
## Figma Make 프롬프트 — {이슈 ID}: {제목}

```text
Task: {한 문장. 무엇을, 어떤 플랫폼에서, 몇 개 화면 세트인지}

Context: {왜 필요한지 + 사용자/상황. 1~2문장}

Screens:
- {화면1 이름} — {한 줄 역할}
- {화면2 이름} — {한 줄 역할}

Elements:
- {화면별 핵심 UI 컴포넌트들}

Behavior:
- {사용자 동작 → 시스템 반응}
- States: 기본 / 빈 / 로딩 / 에러 / 성공

Constraints:
- {플랫폼·디자인 톤·라이트/다크·언어·접근성·더미데이터}
- {바뀌면 안 되는 것}
```

**Figma Make 사용 팁**: 위 블록을 그대로 붙여넣기 → 초안 생성 후 수정은 새 프롬프트에 `Constraints:`로 "유지할 것"을 명시해 의도치 않은 변경 방지. 참조 디자인이 있으면 스크린샷 대신 **프레임**을 첨부. 구조적 후속(TC-EBC)엔 Claude Sonnet, 좁은 수정(아이콘 교체·리네임)엔 빠른 모델 권장.
````

프롬프트가 완성되면 사용자가 직접 **Figma Make 채팅창에 붙여넣어** 초안을 생성한다. 후속 수정도 같은 방식 — 새 프롬프트에 `Constraints:`로 "유지할 것"을 명시해 의도치 않은 변경을 막는다.

## 예시 — `BKT-262` (책 검색 + 추가 화면, 알라딘)

입력 이슈를 위 규칙으로 변환한 결과:

```text
Task: 독서 메모 앱의 "책 검색 → 추가" 플로우를 모바일(iOS 스타일) 화면 세트로 디자인. 서재의 [+]에서 진입하는 검색·결과·상세확인·저장 흐름.

Context: 모든 메모는 책에 종속되므로 책 추가가 메모 입력의 첫 관문이다. 사용자는 방금 읽기 시작한 책을 검색해 빠르게 서재에 넣고 싶어 한다.

Screens:
- 검색 화면 — 검색어 입력 + 실시간 결과 리스트
- 책 상세 확인 시트 — 추가 전 메타 확인 + "왜 읽는지" 입력 + 저장
- 빈/에러 상태 — 결과 0건, 중복, 네트워크 실패

Elements:
- 검색 화면: 상단 검색 input(자동 포커스, 플레이스홀더 "제목·저자 검색"), 결과 리스트 셀(표지 썸네일 + 제목 + 저자)
- 상세 확인 시트(하단 슬라이드업): 큰 표지, 제목·저자·출판사·출간일, "왜 읽는지" 1줄 입력(선택), [서재에 추가] 기본 버튼
- 빈 상태: "검색 결과가 없어요" + [직접 추가] CTA
- 토스트: 중복 시 "이미 서재에 있어요"(→ 해당 책 상세로 이동), 네트워크 실패 시 재시도 토스트(입력값 유지)

Behavior:
- 검색어 입력 → 표지+제목+저자 결과 리스트 갱신
- 결과 항목 탭 → 상세 확인 시트 슬라이드업
- [서재에 추가] → 성공 후 서재로 복귀, 새 책이 표지+제목 카드로 표시
- States: 기본(결과 있음) / 빈(0건→직접 추가) / 로딩(검색 중 스켈레톤) / 에러(네트워크 실패 토스트) / 중복(저장 차단 토스트)

Constraints:
- 모바일 우선, iOS Human Interface 톤(시스템 폰트, 둥근 카드, 안전영역 여백)
- 라이트/다크 모드 모두
- 모든 카피는 한국어
- 더미 데이터는 실제 한국 단행본(표지 느낌·제목·저자)로 현실감 있게 채울 것
- 접근성: 표지 이미지 대체텍스트, 최소 탭 타깃 44pt
- 데이터/API/백엔드 로직은 다루지 말 것 — UI와 상태만
```

> 변환 메모: 알라딘 `ItemSearch`/`ItemLookUp`·SwiftData·Firestore 같은 구현 디테일은 프롬프트에서 제거하고, **화면에 보이는 필드**(표지/제목/저자/출판사/출간일)와 **엣지 케이스 → 상태 화면**만 남겼다.
