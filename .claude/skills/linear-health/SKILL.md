# /linear-health [프로젝트] — 이슈 상태 헬스체크 (수동 호출)

0901 대청소에서 수동으로 찾아낸 신호들을 한 번에 훑는다. 기본 대상: 현재 레포의 팀(Booktracking 이면 Release 프로젝트).
**리포트 전용** — 발견한 것을 고치는 건 준서 지시 후 (`/linear-audit`·`/linear-merge`·`/issue-lint` 로 이어짐).

## 점검 4가지

### 1. 커밋은 있는데 상태가 Backlog/Todo
- `git log --oneline --since="90 days ago"` 에서 이슈 번호(`BKT-\d+` 등) 추출
- 각 번호의 이슈 상태 조회 — Backlog/Todo 인데 feat/fix 커밋이 있으면 **구현 미기록 후보** (사례: BKT-330·383 이 이걸로 잡혔을 것)

### 2. In Review 적체
- `list_issues(state: "In Review")` — 2주 이상 머문 것(stateHistory 진입 시각 기준)
- 각각에 대해 "닫아도 되는가" 판정: 목표 체크리스트 완료율 + 결과 기록 유무 + 미완 항목이 이 이슈 몫인지(아니면 후속 이슈로 넘기고 닫을 수 있는지)
- 판정 예시: 미완 항목이 다른 이슈 몫이면 "이관 후 Done 가능" (BKT-331 위키 캐스케이드 사례)

### 3. 결과가 빈 채 커밋만 쌓인 이슈
- 본문 `## 결과` 가 비었거나 자동 커밋 콜랩스만 있는 이슈 — post-commit 훅이 "결과에 직접 쓸 것"을 남긴 채 방치된 것들

### 4. 죽은 링크
- Canceled·통합(포인터 스텁) 이슈를 본문에서 가리키는 활성 이슈

## 리포트 형식

이슈별 한 줄 — `번호 · 제목 · 신호 · 추천 조치(Done 처리 / 결과 기록 / 이관 / 통합 / 재작성)`.
확신 없는 판정은 근거와 함께 물음표로. 기록하지 말고 대화로만 보고 (준서가 고를 것).

## 하지 않는 것
- 이슈 수정·상태 변경 (리포트 후 지시받아 실행)
- 90일 밖 히스토리 전수 조사 (요청 시에만)
